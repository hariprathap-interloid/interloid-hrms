# Vite Starter Template — Senior Frontend Review

**Date:** 2026-07-07
**Reviewer:** Senior Frontend Engineer (Claude)
**Scope:** Folder structure · Services layer · Design-system adoption · Tailwind configuration

## Overall Score: **6.5 / 10**

A thoughtfully assembled, modern foundation with excellent tooling discipline, held back
by an unfinished data/services layer and a broken (contradictory) dark-mode setup. Strong
bones; not yet a "clone-and-build-features" starter for an HRMS.

## Priority Findings

### P0 — Broken / immediate

1. **`components.json` CSS path is wrong.** Declares `"css": "src/index.css"` but the file
   is `src/styles/index.css`. Next `npx shadcn add <component>` mislocates token injection.
   → Fix path to `src/styles/index.css`.

2. **Dark mode is non-functional.** Two conflicting strategies:
   - `.dark {}` + `@custom-variant dark` override the real shadcn tokens — but nothing sets
     the `.dark` class (no theme provider/toggle).
   - `@media (prefers-color-scheme: dark)` only overrides **legacy** vars (`--text`, `--bg`,
     `--accent`…) that aren't exposed via `@theme`, so they drive no component.
   → Pick one strategy. Add a `ThemeProvider` toggling `.dark` (persisted + system default).

### P1 — Architectural gaps

3. **No services / data layer** (biggest gap for an HRMS).
   - `src/services/` empty; `features/auth/api.ts` is a committed 0-byte file.
   - `VITE_API_URL` is validated but consumed nowhere.
   - No HTTP client (base URL, auth-token injection, error normalization, JSON/Zod parsing).
   - No server-state library.
   → Add **TanStack Query** + `services/api-client.ts`. Define the boundary explicitly:
     `services/` = transport/client; `features/*/api.ts` = feature endpoint functions on top.

4. **No provider composition in `app/`.** `app.tsx` is bare `<RouterProvider>`.
   → Introduce `app/providers/` (QueryClientProvider → ThemeProvider → ErrorBoundary → Router).

5. **No app-level error boundary.** Router `errorElement` only catches routing/loader errors,
   not render errors. → Add `react-error-boundary` at the provider level.

### P2 — Design system & Tailwind cleanup

6. **Two competing token systems in `index.css`.** Legacy vars (`--text`, `--bg`, `--accent-bg`,
   `--social-bg`, `--shadow`, `--code-bg`) look copied from an unrelated template, are not exposed
   through `@theme inline`, and are effectively dead. → Delete or intentionally promote into `@theme`.

7. **Design system not applied to shipped pages.** `error.tsx`, `not-found.tsx`, `loading.tsx` are
   raw unstyled `<div>`s; `MainLayout`'s Suspense fallback is a hardcoded `<div>Loading...</div>`
   instead of the existing `LoadingPage` skeleton. These are the reference examples — they should
   model correct token/`Button`/skeleton usage.

8. **`body { height: 100vh }`** clips overflow and has the mobile-viewport bug.
   → Use `min-h-dvh`. (`--font-heading` = `--font-sans` is also redundant.)

9. **Redundant loading paths.** Per-route `HydrateFallback` + layout `<Suspense>` overlap.
   → Standardize on one and route it through the real skeleton.

### P3 — Template hygiene

10. **Empty committed files** (`features/auth/api.ts|hooks.ts|types.ts`, 0 bytes) contradict the
    project's own `.gitkeep`/"add when it has real content" rule. → Remove until auth is built.
11. **No test setup.** → Add Vitest + Testing Library + one example test.
12. **No CI workflow.** → `.github/workflows` running `tsc -b`, `eslint .`, `build`, tests.
13. **Docker/nginx hardening** (low, internal tool): no security headers
    (`X-Frame-Options`, `X-Content-Type-Options`, CSP); container runs as root.

## Recommendations to Make This a Best-in-Class Vite Starter

**Data & state (highest leverage)**
- TanStack Query for server state; a typed `api-client` reading `env.VITE_API_URL`.
- Zod-parse API responses at the boundary (you already depend on Zod).
- A worked `auth` feature end-to-end (login form → api → hook → protected route) as the reference slice.

**Design system**
- One dark-mode source of truth + `ThemeProvider` and a toggle in the layout.
- Collapse to a single token system; delete legacy vars.
- Style the error/404/loading pages with the design system as canonical examples.
- Add 3–4 more base primitives (input, card, dialog, form) so forms — an HRMS staple — are ready.

**Quality gates**
- Vitest + Testing Library + example unit/component test.
- Playwright smoke test (a `webapp-testing` style check) for the critical route.
- GitHub Actions CI mirroring the pre-commit gate.
- Consider `knip` for dead-code/dep detection (would have caught the unused legacy tokens).

**DX & structure**
- `app/providers/` composition root.
- Document the `services/` vs `features/*/api.ts` boundary in `dev.md`.
- Route constants already good (`paths.ts`) — extend the `getHref` pattern for params.
- Optional: a `RouteErrorBoundary` per feature for graceful degradation.

**Production readiness**
- nginx security headers + gzip/brotli; non-root Docker user; healthcheck.
- Consider runtime config injection (an `env.js` templated at container start) so one image
  serves multiple environments without rebuilds — the current build-time bake means one image
  per environment.

---

## Bottom line

Keep the tooling and structure — they're above average. Prioritize, in order:
(1) fix `components.json` path, (2) consolidate dark mode, (3) stand up the services + TanStack
Query layer with a real auth slice, (4) add tests + CI. Those four move this from a
**6.5** scaffold to a genuine **9** production starter.
